## ═══ CROSS-CUTTING FINDING (affects ~11 of the 25) ═══

**THE FORGEJO + JENKINS SUBSTRATE IS STALE CANON.** The single largest contradiction in this id-band: a whole
cluster of Accepted ADRs (0363, 0365, 0366, 0367, 0369, 0370, 0371, 0374, 0375, 0378, 0380, plus the console in
0391) is built on the **"git + Jenkins + self-hosted Forgejo"** substrate. The founder rulings reverse BOTH legs:

- **D2 (canon line 152–154):** "GitHub NOW → bespoke VCS LATER … **Forgejo is dropped as the transitional.**"
- **D-FORGE-CLARIFY (line 206–207):** "**Forgejo is DROPPED entirely** — NOT a bridge adapter. **GitHub is the ONLY interim forge** … bespoke, Sapling-inspired SCM … FIX = a **systematic Forgejo-eradication sweep**."
- **D3 / D-CICD (line 156–161, 168–169):** the CI substrate = the unified **oya-ci** product (ADR-0513 → new ADR-0515), with "**Jenkins (0349/0359/0361) + Argo stay OPERATIVE until oya-ci is built and proven → cutover → THEN retire** (mark 'superseded-on-cutover', NOT archived now)."

So every ADR that names Jenkins/Forgejo as the *destination* substrate (not an explicitly-unratified bridge) is in
canon-contradiction. Per build-first-cutover-later (D-META, line 26) these are **AMEND** (re-frame Jenkins/Forgejo as
the unratified de-facto bridge; point CI authority at oya-ci; sweep Forgejo→GitHub-interim) — **not ARCHIVE**, because
the owned replacement (oya-ci) is not yet built+proven. This is exactly the "CC-4 Jenkins/ArgoCD-as-canonical→oya-ci"
+ "CC-5 Forgejo→GitHub-now" amendment already enumerated in WF2 (canon line 150).
