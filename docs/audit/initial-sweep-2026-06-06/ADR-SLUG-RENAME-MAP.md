## Repoint mechanics (verified, applies to ALL rows)

1. **Frontmatter cross-refs need NO repoint.** ADR frontmatter `supersedes` / `superseded_by`
   / `amends` / `amended_by` / `related` use **bare `ADR-NNNN`** (e.g.
   `supersedes: [ADR-0110, ADR-0112, ADR-0113]`), never the full slug. A slug rename does
   not touch these arrays. **Zero frontmatter repoints across all 21 ADRs.**
2. **No Obsidian `[[wikilinks]]` exist** anywhere in the corpus. All references are either
   markdown links `[ADR-NNNN](decisions/ADR-NNNN-slug.md)`, relative `source_adr:` paths,
   or INDEX/CATALOG table cells embedding the `.md` filename.
3. **The actual hand-repoint surface = `.md`-suffixed link/path targets** carrying the slug.
   Every reference to an in-scope slug is `.md`-suffixed (verified: ADR-0347 = 102/102 refs
   carry `.md`, 0 bare). Repoint = rewrite the link target path.
4. **Generated faces are NOT hand-repointed.** `cloud/cloud-ci/gates/accounting-registry-producer/*.generated.json`
   (`accounting-registry`, `gate-baseline`, `enforcement-inventory`) and the generated rows of
   `docs/ADR-INDEX.md` + `docs/machine-readable/decisions.json` ("Generated by `oya doc adr-index`;
   do not hand-edit generated rows") **regenerate after the rename** via the spine. They appear in
   the census for completeness but are auto-resolved, NOT manual edits.
5. **`ADR-INVENTORY.tsv` / `DOC-CATALOG.md`** carry the filename in a cell and must be updated
   (or regenerated if produced by a tool — verify producer before hand-editing).

## RISKY rows (flagged — do not rename blind)

1. **ADR-0347 `foundry-fitness-to-governance-bulk-rename`** — **highest blast radius**: 101 referencing
   files, 96 of them service `README.md` files + `docs/AGENTS.md` + `AGENTS-OPERATING-CONTRACT.md`,
   each citing it as active operating-contract doctrine. The slug *names the rename event itself*; the
   word "foundry" here is the historical subject of the rename (foundry-fitness → governance). Renaming
   the slug to drop "foundry" partially erases what the ADR documents. **Recommendation:** if renamed,
   use `governance-fitness-bulk-rename` and stage as its own PR with a dedicated 96-file repoint sweep;
   otherwise KEEP the slug as load-bearing historical and rely on prose, not filename, for vocab hygiene.

2. **ADR-0363 `retire-agentic-vcs-foundry-to-intelligence-forgejo-substrate`** — carries **three**
   forbidden tokens (`vcs`, `foundry`, `forgejo`), but ALL are load-bearing historical: the slug literally
   enumerates what was retired and where it moved. Only 2 references (both generated faces). **Recommendation:**
   KEEP as-is (historical retirement record) OR, if a clean slug is mandated, `retire-agentic-vcs-platform-to-intelligence-on-github-substrate`
   — but note this loses the precise "Foundry" referent that ADR-0362/0335 chain to.

3. **ADR-0335 `foundry-microservice-retired-absorbed-by-intelligence`** — the slug records the foundry→intelligence
   retirement; "foundry" is the historical subject. 20 refs incl. 15 cross-cite ADRs. Risk = renaming erases the
   retired-thing's name. **Recommendation:** if renamed, `intelligence-absorbs-retired-foundry-microservice`
   keeps the historical referent while leading with the destination; or KEEP.

4. **ADR-0374 + ADR-0387** — both slugs contain BOTH `forgejo` AND `jenkins`. The jenkins token is owned by the
   **separate jenkins wave**. Renaming only the forgejo portion here would leave `jenkins` in the slug, requiring
   a SECOND rename in the jenkins wave. ADR-0374 `related_specs` also points at
   `/infra/ci/jenkins/reported-status-contexts.json`. **Recommendation:** COORDINATE with the jenkins wave —
   rename both tokens in one pass (`ci-webhook-gateway-github-jenkins` is only an interim; final jenkins-wave slug
   may be `...github-<successor-ci>`).

5. **ADR-0377 frozen gate-test fixture** — `specs/fixtures/cross-artifact-agreement/tc-XA-bad-dup-adr-number.json`
   embeds the literal string `docs/adr-archive/ADR-0377-github-board-git-ref-cas-fallback.md` as a synthetic
   duplicate-ID exhibit. It is a FROZEN test exhibit (not a real-path assertion), but a rename would desync the
   fixture string from the real filename. **Recommendation:** update the fixture string in lockstep, or confirm the
   gate matches by `id` not filename before renaming.
