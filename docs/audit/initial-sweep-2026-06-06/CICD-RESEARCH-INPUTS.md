## 3 — EXTERNAL BEST-PRACTICE (deep-research, cited)
- **Throughput (ROI order):** affected-target/incremental from a reverse-dep graph (Google TAP; Buck2 native target-determinator) → **RE + remote cache** (Buck2 speaks Bazel RE-API: EngFlow/BuildBarn/BuildBuddy/NativeLink) → **presubmit/postsubmit split** (fast+reliable gate merges; comprehensive runs postsubmit) → **speculative merge queue** (Uber SubmitQueue: −53% CI / −44% CPU / −37% p95) → milestone batching at extreme scale.
- **Surface-all w/o losing speed:** fan-out concurrent, **none short-circuits**, aggregate at join. `cargo-nextest --failure-output=immediate-final` + JUnit XML; `dorny/test-reporter` glob-aggregates shards → one Check-Run + Job Summary; problem-matchers → inline annotations (capped 10/step·50/job·50/run → pair with the aggregated summary).
- **Anti-patterns:** flaky-test tolerance (Google: ~1.5% of runs flake, ~16% of tests ever flaky); per-commit full-suite (quadratic compute); **false-green/non-blocking required checks**; fail-fast hiding downstream errors; unpinned/non-reproducible builds; manual gates that drift; self-approval.
- **Rollout (data-driven):** 91.3% of affected tests never fail; per-change pass:fail ≈ 99:1 → **shadow → ratchet(block-on-new) → required** is the validated path. Refs: `imbue-ai/ratchets`, GitHub rulesets best-practice, Prow Tide config.
- **Honest gaps (not substantiated by surviving claims):** the GH-Actions→owned-Prow/Tekton/Argo migration mechanics, signed-commit enforcement specifics, and shadow-control-plane mirroring — our design must resolve these itself (Prow Tide + rulesets primary sources only).

## 4 — THROUGHPUT PLAN (all preserve surface-all)
1. **Generate-once-share the producer:** one `produce --out-dir <faces>` writes all 5 faces; every gate test + registry-drift + firewall reads it via `PRODUCER_FACES_DIR` instead of each shelling `cargo run`. Collapses ~a-dozen ~12s producer runs/cycle → ONE.
2. **O(1) token-index for `resolve_reachability`** (pattern already in `resolve_justifications`): removes ~12.45 GB substring scan; ~12s → ~1.4s.
3. **Exec the buck2-built producer artifact** (`$(exe …)`), not `Command::new(CARGO).arg("run")` — content-addressed, 0 recompiles when unchanged.
4. **Buck2 remote/shared read-through action cache** for CI runners (+`actions/cache` for buck2 binary + rustup); RBE as stretch.
5. **Four-stage split** (see §6): presubmit = affected-closure (blocking/fast); whole-graph `//:...-check` → postsubmit + periodic; extend affected-targeting to governance/authority/coverage lanes; de-dup the 7-command list repeated across fanout/required/cd-dry-run.
6. **Merge queue** (GitHub `merge_group` interim; own Tide-invariant serial batch at oya-ci Phase-1): whole-tree firewall regen runs once per BATCH (~/N), closes the `strict:false` stale-merge hole.
7. **Split registry-drift's 5-face test into 5 per-face tests** (after generate-once) → nextest fans them parallel, sub-second.
8. **Throughput SLOs + flake quarantine** (quarantine list is DATA emitting a burn-down; gate the Phase-3 speculation-tree behind a measured queue-p50 SLO).

## 5 — SURFACE-ALL DESIGN (two-level: parallel at top, collect-all at bottom)
- **L1 parallel/fast (keep):** matrix `fail-fast:false` + `max-parallel` so lanes never cancel each other.
- **L2 collect-all (the missing piece):** build `cloud-ci-firewall`'s **absent `main.rs`/bin** as the SINGLE aggregation entrypoint — runs every gate's `evaluate_keyed` (all collect ALL findings, no early return), emits ONE `FirewallReport` → a GitHub **Check-Run with per-finding inline annotations + one summary listing EVERY failure across all gates + a persisted advisory burn-down**.
- **Kill fail-fast:** required GitHub context becomes a **pure ZERO-BUILD fan-in** (`needs:[all-lanes]`, `exit 0`) — green IFF every lane is green; it must NEVER run its own narrower command set. Stopgap for sequential shell: `buck2 build … --keep-going`.

- **A — App-posted commit-status FIRST (recommended).** Make `oya-ci-required` a branch-agnostic GitHub-App status from the oya-ci-controller Job image (firewall aggregator out-of-tree), shadow until verdict-agreement, then ADD alongside. **Pros:** dissolves disjoint-history entirely (App status needs no shared history); zero-regression ADD; RED/GREEN proven in shadow; controller seam exists. **Cons:** no LIVE producer today (controller is shadow → with-infra); surface-all UX must come from inside the Job (Check-Run), not the 240-char status line.
