# ADR-0595: De-commit the pure-derivation cloud-ci accounting faces

## Status

**Proposed - 2026-06-23 (authored for founder sign-off; door: one-way — once the
re-tracking guard lands, the policy class "pure-derivation faces are not contributor merge
surfaces" is a one-way commitment).**

## Context

Six generated faces under
`ci/facade/artifact-inventory-registry/` were git-tracked despite the
repo-wide `.gitignore` `**/*.generated.json` rule (they were force-added):

| Face | Content | Human bits |
|---|---|---|
| `accounting-registry.generated.json` (~11.6 MB) | git ls-files × OWNERS × ADR front-matter × specs | none |
| `gate-baseline.generated.json` (~3.5 MB) | enumerated currently-failing keys | none (policy lives in `src/gate-disposition.json`) |
| `decision-crosswalk.generated.json` | projection of ADR front-matter/specs | none |
| `enforcement-inventory.generated.json` | projection of gates/** + oya-ci.toml | none |
| `enforcement-liveness.generated.json` | projection of hook wiring | none |
| `ttl-policy.generated.json` | expansion of `src/ttl-policy.json` | none |

Each is a pure deterministic function of `(tracked tree × small committed policy)`. Because the
settle protocol regenerates faces in any PR that touches a non-generated path, and the freshness
gate enforced committed==regenerated byte parity, every PR rewrote these multi-MB blobs — making
them an all-pairs merge-conflict surface that single-threaded the merge queue. This was the #1
merge-conflict / merge-queue friction. The founder directive (2026-06-09): "the generated json
merge conflict is friction — it should either be gitignored or we need a better way."

ADR-0551 (merge-base frozen-baseline ratchet) and ADR-0552 (stable/volatile scm-facts split)
already removed the firewall's and the squash-merge churn's dependence on committed face bytes:
the firewall loads its frozen reference from the out-of-graph merge-base snapshot and computes
the proposed baseline by exec-ing the buck2-built producer — it never reads a committed
accounting face. This ADR completes the de-commit they began, for the six remaining producer
faces.

## Decision

STOP committing the six producer faces above. They are declared `materialization_mode:
not-tracked-in-git` in `registry/generated-artifact-control-plane.json`, removed from git
(`git rm --cached`), and covered by the existing `**/*.generated.json` ignore. They are derived
on demand via `buck2 run //ci/facade/generated-artifact-freshness:oya-cloud-ci-materialize-generated-faces-bin` and materialized out-of-graph
for consumers before gates run.

KEEP committed (human inputs / control surface, unchanged):
`firewall/gate-baseline.signoff.json` (the one-way debt door), `firewall/ratchet-policy.json`
(policy DATA), `registry/generated-artifact-control-plane.json` (the control surface), the
producer's `src/ttl-policy.json` / `src/gate-disposition.json` policy SOURCES, and all upstream
sources (OWNERS, ADR front-matter, oya-ci.toml, specs/**). `specs/reorg/move-manifest.generated.json`
stays committed (already special-cased).

`scm-facts.generated.json` is NOT de-committed by this ADR. It is a declared hermetic input to
~20 gate tests; its de-commit requires a dedicated repoint pass (each reader must point at the
materialized path) and is deferred to its own follow-up IP. Its volatile half is already
de-committed (ADR-0552).

### Gate teaching (the no-flag-day mechanics)

1. **Control-plane gate** (`oya-cloud-ci-generated-artifact-control-plane-app`): a new
   `materialization_mode` value `not-tracked-in-git`. A declared path in this mode is EXEMPT
   from `generated_artifact_declared_path_not_tracked` (its absence from the tracked tree is the
   desired state). Symmetrically, a `not-tracked-in-git` path that IS tracked fires a new
   `generated_artifact_not_tracked_path_is_tracked` finding — the one-way door that makes
   re-committing a de-committed face a hard RED. No-op for still-committed artifacts.

2. **Freshness gate** (`oya-cloud-ci-freshness-app`): the byte-parity predicate
   (committed bytes == regenerated bytes) is retired ONLY for de-commit-class faces (read from
   the control-plane manifest's `materialization_mode`). For those faces freshness instead
   requires (a) the face regenerates successfully and (b) it is byte-stable across two
   regenerations (the determinism canary, `evaluate_face_determinism`). Committed-class faces
   (e.g. move-manifest, scm-facts) keep their byte-parity check unchanged.

3. **`.gitignore`**: documents the de-commit; the six paths are covered by the existing
   `**/*.generated.json` rule and are intentionally NOT negated (unlike move-manifest).

## Consequences

- The six faces are never in a PR diff, so they can no longer conflict — the merge-conflict /
  merge-queue friction class is eliminated for them.
- Determinism becomes the load-bearing integrity invariant (it was previously masked by
  byte-equality-to-committed). The regenerate-twice canary makes a nondeterministic producer
  hard-fail rather than silently green — this is the same cold-vs-warm cache integrity-canary
  doctrine that makes derive-don't-commit sound.
- Born-accounting / register-crate remain fully enforceable: the registry is DERIVED and
  validated each PR by exec-ing the producer; nothing about born-accounting depended on the
  bytes being committed (the firewall already proves this).
- registry-drift's `committed_faces_equal_regenerated` now byte-compares the MATERIALIZED
  on-disk face (written by the materializer before gates run) against a fresh regeneration —
  i.e. a determinism check — for the de-commit-class faces. The materialization step must run
  before gates (already steady state per ADR-0551).
- The materializer is now the Rust/Buck2 binary
  `//ci/facade/generated-artifact-freshness:oya-cloud-ci-materialize-generated-faces-bin`.
  The former shell bridge has been retired; the remaining long-term target is an owned
  Rust/controller materialization path in cloud-ci.

## Alternatives considered

- **Keep committing + a merge driver** (ADR-0558 scope): a structural-union merge driver still
  leaves the multi-MB faces in every PR diff and re-derives them on every touch. De-committing
  removes the surface entirely; the only residual merge surface is the human `signoff.json`,
  which is the proper scope for a server-side union driver.
- **Commit a slim "ratchet datum"**: unnecessary — the merge-base materialization (ADR-0551) +
  committed `src/gate-disposition.json` already supply the frozen reference and per-code policy.
  A new committed datum would re-create a churning surface.

## Born-accounting

This ADR adds one decision node (ADR-0595) consumed by the accounting-registry producer's ADR
front-matter projection and the decision-crosswalk. It adds no new crate; the gate changes are
edits to two existing gate crates (control-plane, freshness) and one new
`materialization_mode` enum value. The de-committed faces leave the accounting registry's
tracked-output set but remain DECLARED in the control-plane manifest, so the registry's
declared-artifact accounting is unchanged in shape.

## Supersedes / feeds

- Completes (does NOT supersede) ADR-0551 and ADR-0552 for the remaining producer faces.
- Feeds ADR-0558 (faces merge driver): after this de-commit the only residual merge surface is
  the signoff door; the driver should be scoped to that file only.
- Forward-compatible with the corpus live-AST-graph (derive global on main, per-cap shards):
  derive-don't-commit is the CI-faces instance of de-globalizing the registry.
