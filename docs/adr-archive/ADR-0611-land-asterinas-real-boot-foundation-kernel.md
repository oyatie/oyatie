# ADR-0611: Land the Asterinas real-boot foundation harness under kernel/ (kuberos Wave-1 shard-1)

## Status

Proposed (2026-07-04).

## Context

ADR-0512 sanctions a single nested/excluded Cargo workspace at top-level `kernel/` (the rung-0 kuberos kernel; the `no_std`+custom-sysroot rung cannot share the std-targeted root lockfile), and ADR-0562 registers `kernel/` as a closed-registry meta-dir. Until now `kernel/` was empty on `dev`.

The kuberos Wave-1 program adopts the unmodified upstream **Asterinas** kernel as a black-box artifact behind rule-gated adapters. Its foundational evidence requirement is a **real boot**: prove the pinned upstream Asterinas v0.17.2 release ISO boots in QEMU to a boot-ready userland, with admissible (non-simulated) evidence, *before* scaling to the full soak battery. Earlier full-seed attempts produced simulated (rejected) or envelope-crashed evidence; this shard (shard-1) de-risks the real-boot execution envelope to a single verified boot.

This ADR is scoped to **landing that foundation** — it is the governed-path justification (ADR-0555) for the first `kernel/` population. The broader product decision (Asterinas AS the canonical kuberos kernel, and the multi-shard Wave-1 roadmap) remains a separate founder-authored pivot ADR; nothing here decides that.

## Decision

Land, under the sanctioned `kernel/` nested workspace, one owned-Rust deliverable:

1. **`kernel/core/asterinas-boundary`** — a zero-dependency compile-time boundary crate: the black-box pin of the upstream release ISO (`asterinas-release-v0.17.2.json`, digest-embedded via `include_str!` so pin and manifest cannot drift) and the **closed** boot-ready marker set (login / shell / `Welcome to NixOS` / systemd startup / `Reached target …`). No fallback/heuristic marker.
2. **`kernel/harness/asterinas-real-boot`** — a dev-only QEMU harness (a pure library + thin `std::process` binaries): fetch+verify the ISO by digest (owned typed HTTP), boot it **once** in `qemu-system-x86_64` (software TCG), drive the ISO's ISOLINUX `boot-serial` entry over serial to obtain `console=ttyS0` userland output, capture raw serial verbatim to a file, derive a boot verdict **solely** from the closed marker set, recompute and fail-closed self-check the receipt digest, and emit an honest-fail gap-register entry on non-boot. The verdict is `marker_present && iso_digest_verified`; the marker itself proves the serial-console entry booted (the VGA-only default emits nothing to serial), so no fabricated PASS is representable.

Doctrine held: owned-Rust / no-shell (ADR-0523) — the only non-Rust surfaces are the `qemu-system` binary and the release-asset download; `#![forbid(unsafe_code)]` throughout; unit + integration tests run via `buck2 test`. Large artifacts (ISO, serial log) are referenced by path+digest, never inlined; `target/` and the harness `receipts/` are gitignored (evidence is regenerated by re-running the harness — a CI evidence gate must re-run it, never trust a checked-in receipt).

Placement/accounting: `kernel/` is excluded from the root Cargo workspace (mirrors the `cloud/cloud-kernel` nested-workspace precedent); admitted in the ADR-0600 root-workspace-hygiene `allowed_root_dirs`; registered as a reached tree in `specs/reachability-registry.json`; owned by `council-architecture`.

## Consequences

**Positive:** the sanctioned `kernel/` workspace is populated with a verified-real, adversarially-reviewed boot foundation; the boundary-crate compile-time-pin pattern is reusable for future upstream pins; the anti-simulation properties are unit-tested (not narrated). **Cost:** a dev-only QEMU harness under `kernel/`; the soak shard (10 consecutive clean cold boots) and the product-pivot ADR follow separately. **Neutral:** no runtime product surface, no audit-chain emission.

- `kernel/Cargo.lock` — the nested workspace's own lockfile (kept tracked).
- `kernel/OWNERS` — ownership marker for the `kernel/` tree.
- `kernel/core/asterinas-boundary/Cargo.toml` — boundary crate manifest.
- `kernel/core/asterinas-boundary/BUCK` — boundary crate buck2 targets.
- `kernel/core/asterinas-boundary/pins/asterinas-release-v0.17.2.json` — the black-box upstream ISO pin (digest + closed marker set source).
- `kernel/core/asterinas-boundary/src/lib.rs` — the pin + closed boot-ready marker constants.
- `kernel/harness/asterinas-real-boot/Cargo.toml` — harness crate manifest.
- `kernel/harness/asterinas-real-boot/BUCK` — harness buck2 targets (lib + fetch-verify/boot binaries + unit + integration tests).
- `kernel/harness/asterinas-real-boot/src/lib.rs` — pure fetch-verify + boot-verdict + receipt-assembly logic (unit-tested, no QEMU/network).

- `kernel/harness/asterinas-real-boot/src/main.rs` — the fetch-verify binary.
- `kernel/harness/asterinas-real-boot/tests/boot_finalize_integration.rs` — receipt/honest-fail integration test.
