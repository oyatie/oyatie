# ci — the config-driven conformance FLOOR

ci is a portable, config-driven conformance engine: a deterministic **producer** builds a set
of generated *faces* from the tracked repo, a shrink-only **firewall ratchet** blocks any NEW
policy violation while tolerating the frozen pre-existing debt, and a **registry-drift** byte-diff
makes the faces tamper-evident. The engine is generic; only the *policy* is per-repo, and the
policy is DATA in a single `ci.toml` at the repo root.

This directory is the FLOOR documentation (OYA-CI-CONFORMANCE-FLOOR-PLAN §6). It covers what a repo
needs to adopt the floor; the broader product north-star (third-party gate SDK, cloud control
plane, hermetic build backends, non-Rust gate packs) is a separate, later workstream and is NOT
documented here.

## The engine vs the policy (the load-bearing seam)

| Layer | What it is | Where it lives |
|---|---|---|
| **Engine (generic, fixed)** | the ratchet (compare-mode + ratchet-invariant), registry-drift byte-parity, the `Finding`/`evaluate_keyed` contract, `build_gate_baseline`'s disposition join, the one-way sign-off door | the gate crates + the firewall crate — touched by NO per-repo config |
| **Policy (per-repo, DATA)** | naming tables, forbidden-vocab tables, manifest field-set, repo roots + path-excludes, reachability/justification/owners/enforcement sources, ttl + unit-class tables, the enabled-gate set + each gate's input KIND + per-(gate,code) dispositions | `ci.toml` (closed-schema), parsed by the `ci-config-kernel` crate |

A repo with **no** `ci.toml` gets a sane bundled default: language-agnostic gates present but
quiet (empty policy tables), no false RED. Adding config *widens* enforcement. The schema is
**closed** — an unknown key is a hard error, so the shared spine cannot silently drift.

## Components

- **Config kernel** — `libs/ci-config` (crate `ci-config-kernel`): the closed-schema,
  I/O-free TOML loader + the bundled default.
- **Producer** — `cloud/cloud-ci/gates/cloud-ci-accounting-registry-app`: the `rust_binary`
  that reads `ci.toml`, runs git plumbing, and emits the generated faces (including
  `gate-baseline.generated.json`). NOT a CLI subcommand.
- **Firewall** — `cloud/cloud-ci/gates/cloud-ci-firewall-app`: the shrink-only ratchet runner.
- **registry-drift** — `cloud/cloud-ci/gates/registry-drift`: the committed==regenerated byte-diff.
- **Gates** — the per-gate `cloud-ci-*-app` crates (each a pure `evaluate_keyed`) + the
  raw-corpus census in `libs/check-brand-residue`.
