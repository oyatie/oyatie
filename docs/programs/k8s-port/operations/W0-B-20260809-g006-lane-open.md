## Judgment

Three things were judged.

**1. Is `specs/port-rules/` reachable-registered today?** No. Measured, not assumed: `specs/reachability-registry.json` carries `specs/k8s-port/` and `docs/programs/k8s-port/` but no `specs/port-rules/` prefix. The first rule record to land would therefore fail ADR-0555 born-accounting as unjustified AND unreachable — a reviewed registry prefix clears both, because REACHED implies JUSTIFIED. This is a precondition rather than a repair: it is registered BEFORE the first record exists, and zero tracked coverage is the declared legal state for a not-yet-committed artifact ("0 is legal for a not-yet-committed artifact — the registration covers it the moment it is tracked").

**2. Does that root need its own `OWNERS`?** No, and the measurement is what settles it rather than a preference. Ownership resolves to the NEAREST ANCESTOR `OWNERS`, and an `OWNERS` covering more paths than `oya-ci.toml [owners] max_paths_per_owners_file` owns NOTHING AT ALL — it fails closed with no fall-through. `specs/OWNERS` names `council-architecture` and `specs/` tracks 373 paths against a cap of 2000, so inheritance is structurally valid with 5.4x headroom. Adding an `OWNERS` here would have been a change that looks like a fix while changing nothing.

**3. Do the program README's `index.json` rows survive the landed gate?** No, and this is the finding of the run. The README traceability table names `specs/port-rules/canary/index.json` (gate liveness) and `specs/port-rules/index.json` (rule liveness). `ci/facade/k8s-program-docs`'s `load_rule_records` walks `specs/port-rules` recursively and returns `R-DOC-RULE-METADATA-MALFORMED` for any path whose extension is not `md`. That is a LOAD error, not a finding: a single `.json` under that root reddens the gate before any other R-DOC check evaluates, so the artifact the README names as the mechanism of rule liveness would instead blind every R-DOC check including rule liveness. The failure mode is the one that matters most here — the artifact that proves the probe ran is the artifact that stops it running.

The contradiction was FILED, not resolved. Neither surface was edited to match the other. Recording it as an owned open question is the correct disposition because the two candidate repairs — creating the JSON, or rewriting the README rows — are opposite governance answers, and picking one silently in an implementation lane would decide a contract by whichever file was cheaper to edit.

- **Findings resolved:** the `index.json` contradiction (Judgment 3) was found by this run and disposed of by filing, not by repair.
- **LANE-RUNNER DEFECT found by this run, recorded because it will recur — the shared-index race.** Two units of this lane ran CONCURRENTLY in the SAME worktree while the sequencing said one must land before the other. A git index is per-worktree and therefore SHARED. This run staged exactly three named files; `git status` at that moment showed the neighbouring unit's work as unstaged and untracked; roughly two minutes later `git commit` produced a SEVEN-file commit, because `git commit` commits the INDEX and the neighbour had staged into it in the interval. Commit `f18a437da` therefore carries four files this run did not author, one of them captured mid-edit.
  - **The class fix, which is worth more than the instance:** "commit named files, never `git add -A`" does NOT protect a lane that shares a worktree, because the protection is on the wrong verb — the hazard is in `commit`, not in `add`. The forms that actually hold are `git commit -- <paths>` (a pathspec-limited commit ignores the rest of the index) or one worktree per unit. This entry's own correction commit uses the pathspec form.
  - **No repair was attempted, deliberately.** `git reset` is forbidden in this lane, and `git commit --amend` rewrites a commit a live neighbouring lane is building on inside the same worktree — the same class of hazard one level up. The commit boundary and the authorship boundary do not coincide for `f18a437da`; that is recorded here rather than corrected, because every available correction risks another lane's work to fix an attribution label.
  - **Second-order effect on this entry:** the `Scope and inputs` and `Gate result` sections were subsequently edited from OUTSIDE this unit to record the same race. The added text was read and checked against measured facts before being carried rather than accepted on sight; it agrees with them. A shared worktree makes a document authored by one unit editable by another, which is the same defect expressed in prose instead of in an index.
