# j54-quote-to-contract-to-payment-saas — Quote To Contract To Payment Saas

## 1. Purpose
A prospect buying Marcus's SaaS under a new tenant exercises one concrete cross-product business workflow: a quote request becomes a contract, first payment, archive, and trial tenant.
This story is intentionally end-to-end rather than surface-local. It proves that identity continuity, tenant scoping, marketplace settlement, audit evidence, and human decision points survive a real business path.
The journey treats the same human as one identity with multiple tenant memberships. Work context is tenant-owned; personal context remains personal-tenant-owned; cross-tenant sharing is explicit, Cedar-permitted, and audit-sealed.
Marketplace settlement is the economic clearing path for tenant deals. Payments executes money movement, but marketplace records buyer, seller, deal terms, fee split, and entitlement state.
Conglomerate tenant hierarchy from ADR-0313 is assumed: parent tenants can own child tenants, but child evidence and personal-tenant evidence are never collapsed into a parent by convenience.
Community behavior follows the TeamBlind + Reddit + LinkedIn + Handshake mixture from the ecosystem catalog: reputation, discussion, recruiting, reviews, and network effects are one governed surface.
All public contracts named in this journey use OpenAPI 3.2.0, AsyncAPI 3.1.0, and proto3. All grammar references use BNF v4.1 and ADR-0105 13-layer vocabulary.
Transport is HTTP/3-first with TLS 1.3, ECH, PQC hybrid negotiation where supported, and strict graceful fallback to HTTP/2 then HTTP/1.1.

| Personal tenant | `__personal__/<principal>` | employer cannot read without lawful scoped process |
| Audience type | `B2B_WORK`, `B2C_CONSUMER`, or journey-specific delegated type | Cedar policy uses this as an input, not a UI hint |

| Audit class | journey-specific class family | every meaningful transition is sealable |

## 4. Failure-Mode Tree
1. Provider outage: workflow-engine pauses the phase, records retry budget, notifies the accountable human, and prevents duplicate settlement with idempotency keys.
2. Policy denial: identity and the caller-side policy library return a typed refusal; no downstream service receives a partially authorized payload.
3. Regional outage: tenancy resolves the DR-pair only when compliance packs allow cross-region continuity; otherwise the user sees a regulator-honest hold state.
4. Key compromise: credential sidecar revokes the OpenBao lease, audit-chain seals the revocation, and workflow-engine switches to human review.
5. Cross-tenant confusion: ADR-0311 default-deny blocks work-tenant access to personal-tenant data and records the attempted scope.
6. Marketplace disagreement: marketplace preserves the canonical deal record, payments preserves ledger facts, and workflow-engine routes dispute or appeal.

## 5. Capacity And Performance Model
Little's Law budget: if the workflow accepts 10,000 active journey instances per hour and each instance holds an average 24-minute active window, the steady-state active instance count is about 4,000.
The p95 synchronous step budget is 250 ms for internal calls, 800 ms for third-party connector calls, and 2 seconds for user-visible aggregate screens.
Backpressure is per tenant, not global. A noisy tenant cannot starve the shared workflow queue or another tenant's marketplace settlement lane.
All metrics carry bounded cardinality: `tenant_tier`, `service`, `journey_id`, `phase`, `status`, and `pack_family`; raw tenant ids stay in logs and traces only under controlled retention.
