# UX Flow — j72-ai-translation-cross-locale-business

## 1. UX Contract
The first screen is the actual work surface, not a marketing explanation. The user sees the active tenant, the human-readable business object, and the next required action.
Work and personal context use visually distinct but restrained context markers. The UI never relies on color alone; every boundary marker has text and accessibility metadata.
Every irreversible action exposes its audit consequence before confirmation. Confirmation appears only for irreversible high-value mutations, not for every normal click.
The UX exposes marketplace settlement as a first-class deal state. Payments status is visible, but marketplace is the authority for buyer, seller, entitlement, fee split, and dispute route.
Contract convention: OpenAPI 3.2.0, AsyncAPI 3.1.0, proto3, BNF v4.1, ADR-0105 13-layer, ADR-0131 flat layout, HTTP/3, ECH, and PQC are visible in developer handoff affordances.

## 3. State Model
| State | User-visible behavior | System behavior |
|---|---|---|
| Ready | primary action enabled | Cedar preflight passed and idempotency key reserved |
| Needs review | human review panel opens | workflow-engine pauses durable run |
| Waiting on counterparty | timeline shows SLA | mail or messenger sends signed request |
| Provider delayed | retry window shown | connect or payments holds idempotent retry |
| Denied | refusal reason shown | audit-chain seals denial class |
| Completed | receipt and evidence links shown | drive/archive and audit-chain are immutable |
