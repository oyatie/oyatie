# Handshake — j65-gdpr-dsar-cascade-across-all-services

## 1. Handshake Invariant
Every edge in this sequence carries tenant context, principal context, audience type, data class, purpose, idempotency key, Cedar decision, and audit event class.
No service calls a PSP, IdP, mail provider, postal API, or other vendor with raw credentials. Provider access goes through OpenBao SecretReference and the library-first credential sidecar.
The sequence uses OpenAPI 3.2.0 for REST, AsyncAPI 3.1.0 for event channels, proto3 for internal streaming or worker calls, and BNF v4.1 for policy grammar references.
HTTP/3 is the preferred transport. QUIC-blocked networks fall back to HTTP/2 then HTTP/1.1; TLS 1.3, ECH, certificate transparency, OCSP stapling, and PQC negotiation are declared at every ingress.

## 2. Sequence
```
01. workflow-engine [dsar-orchestration] -> identity [tenant-scoped contract + audit context]
02. identity [subject-verification] -> tenancy [tenant-scoped contract + audit context]
03. tenancy [tenant-scope-resolution] -> mail [tenant-scoped contract + audit context]
04. mail [mail-export] -> messenger [tenant-scoped contract + audit context]
05. messenger [message-export] -> drive [tenant-scoped contract + audit context]
06. drive [file-export] -> payments [tenant-scoped contract + audit context]
07. payments [receipt-export] -> community [tenant-scoped contract + audit context]
08. community [community-export] -> marketplace [tenant-scoped contract + audit context]
09. marketplace [order-export] -> compliance [tenant-scoped contract + audit context]
10. compliance [gdpr-pack] -> audit-chain [tenant-scoped contract + audit context]
11. audit-chain [dsar-proof] => audit-chain [tenant-scoped contract + audit context]
```

## 5. Observability
Metrics use bounded dimensions. Traces use parent-child spans matching the sequence table. Logs carry schema version and retention class. Audit events are signed, Merkle-sealed, and linked to Drive evidence when an artifact exists.
