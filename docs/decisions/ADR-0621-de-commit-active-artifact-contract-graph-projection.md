# ADR-0621: De-commit the active-artifact-contract graph projection

## Status

**Proposed — 2026-07-24.** Council ratification and acceptance are **not established**: this
two-way candidate awaits qualified-authority review. Protected admission of the implementation
proves only the admitted mechanics and gate behavior; it neither changes this record's lifecycle
nor supplies the missing authority. It is not a legal, operational, custody, affected-party, or
production-readiness claim. It does not authorize roadmap work, dispatch, a feature, migration,
or rollout; all such matters remain on HOLD unless separately authorized.

## Context

`registry/graph/active-artifact-contract-edges.json` is a deterministic projection of the ordered
rows in `registry/artifact-capabilities-registry.json`: one `artifact_id -> artifact_profile`
`declares` edge per row. The active-artifact-contract producer can emit this graph, but the graph
has remained a tracked merge surface without a control-plane declaration or exact generated-path
classification.

Tracked derived bytes can be hand-edited or regenerated alongside a source change, while concurrent
source changes serialize on the same projection. ADR-0613 establishes the stronger invariant for
pure projections: remove the derived bytes from Git, materialize them from the candidate source
tree before consumers run, and prove complete semantic projection, exact bytes, and determinism.

## Candidate proposal

If qualified authority later accepts this candidate, it would:

1. Stop tracking `registry/graph/active-artifact-contract-edges.json`; Git history would remain
   the only committed provenance, with no readable archive or tombstone.
2. Register the exact path as `not-tracked-in-git` with
   `never-manual-merge-regenerate-from-source-tree`. The Buck-built
   `//marketplace/facade/dev-cli:oya` producer operation is
   `emit-active-artifact-contract-graph-edges`.
3. Classify the exact legacy non-`.generated.json` path. Direct add, modify, rename, and copy
   are rejected by generated-output diff policy; deletion remains the retirement transition.
4. Do not add the projection to `registry/artifact-capabilities-registry.json`: that registry is
   a tracked-authority inventory, and registering the de-committed graph would recreate the
   ambiguity this decision removes.
5. The official generated-face materializer emits the graph from the candidate tree before
   consumers run; required-CI transports it to the matrix reader jobs.
6. Require checks to prove one ordered semantic edge per registry row, exact canonical output bytes,
   and independently regenerated byte stability. Missing, malformed, incomplete, reordered, or
   extra output fails closed.

Until acceptance, these are candidate mechanics only, not a binding decision or amendment.

## Consequences

- Protected admission can establish only that the candidate mechanics operate as tested; it cannot
  establish authority, acceptance, or an amendment.
- If accepted, the graph would remain inspectable only after explicit controller materialization
  and absent from a clean checkout by design.
- ADR-0515's protected `oya-ci-required` remains the sole merge authority. Local commands are
  feedback only.
- This record authorizes no roadmap, dispatch, legal, operations, custody, affected-party, or
  production claim.
