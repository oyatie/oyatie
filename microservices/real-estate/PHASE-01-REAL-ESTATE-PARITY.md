# PHASE-01: Real Estate ERP Parity Buildout

## A. Phase intent
This first buildout phase turns the reserved Wave-3-G anchor into an implementation-ready Real Estate service. The phase binds SAP code RE-FX, the bounded contexts lease-contract, facility-master, occupancy-allocation, rent-schedule, lease-accounting-event, facility-service-request, and the PR-143 artifact roster into one delivery sequence. Marketplace remains the settlement authority for tenant deals per ADR-0314; this service owns only the Real Estate domain facts and evidence.

## B. Entry criteria
- Existing PRD, architecture anchor, compliance anchor, and manifest remain intact.
- OpenAPI 3.2.0, AsyncAPI 3.1.0, proto3, BNF v4.1, and ADR-0105 layer names are the only contract spellings.
- HTTP/3 is default, HTTP/2 and HTTP/1.1 are fallback tiers, ECH is advertised where the platform terminates TLS, and PQC hybrid negotiation is offered when peers support it.
- Enterprise precedents for every primitive: SAP RE-FX Flexible Real Estate Management | Oracle Fusion Lease Accounting | Workday Lease Accounting | NetSuite Fixed Assets and lease-accounting counterpart | Microsoft Dynamics 365 Finance Lease Accounting.

## C. Build sequence
1. lease-contract: define kernel value objects, domain invariants, usecase commands, REST and gRPC methods, worker replay path, Cedar gate, SLO, dashboard, catalog record, and migration evidence.
2. facility-master: define kernel value objects, domain invariants, usecase commands, REST and gRPC methods, worker replay path, Cedar gate, SLO, dashboard, catalog record, and migration evidence.
3. occupancy-allocation: define kernel value objects, domain invariants, usecase commands, REST and gRPC methods, worker replay path, Cedar gate, SLO, dashboard, catalog record, and migration evidence.
4. rent-schedule: define kernel value objects, domain invariants, usecase commands, REST and gRPC methods, worker replay path, Cedar gate, SLO, dashboard, catalog record, and migration evidence.
5. lease-accounting-event: define kernel value objects, domain invariants, usecase commands, REST and gRPC methods, worker replay path, Cedar gate, SLO, dashboard, catalog record, and migration evidence.
6. facility-service-request: define kernel value objects, domain invariants, usecase commands, REST and gRPC methods, worker replay path, Cedar gate, SLO, dashboard, catalog record, and migration evidence.

## D. Required deliverables
- Strategic: phase plan, STRIDE threat model, DPIA.
- Operations: README, capacity model, cost budget, failure modes, multi-region, incident response, backfill replay, compliance extension, competitor matrix, SDK plan.
- Policy: one Cedar authorization fragment per bounded context plus abuse-defence, emergency-services bypass, auditor scope, CI scope, and pack overlay authorization.
- Contracts: OpenAPI 3.2.0, AsyncAPI 3.1.0, and proto3.
- Evidence: capabilities, dashboards, SLOs, implementation plans, catalog records, IaC, scorecard overrides, and audit findings.

- Artifact count is at least 100 for this microservice.
- Every bounded context has tenant_id, principal_id, audit_event_class, compliance_packs, provider_credential_mode, and source_system_id in the documented contract.
- Every critical path has an explicit bypass, recovery, audit, or rollback behavior.
- Marketplace settlement is referenced from every tenant-commercial workflow.
