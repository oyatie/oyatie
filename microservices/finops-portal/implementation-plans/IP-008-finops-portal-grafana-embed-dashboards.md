# IP-008 — Grafana-embedded dashboards

## Why this slice

The drill-down dashboards specified in
`dashboards/tenant-cost-drilldown.md` need real Grafana dashboard
JSON to be importable into the Grafana instance per ADR-0186 (Mimir
+ Grafana). Embedding into the `finops-portal` UI is via Grafana's
`iframe` embed + a signed-URL gate; the dashboard authz still flows
through the Cedar policies in IP-007 (because the iframe URL is
generated by the API tier and short-lived).

This slice authors three Grafana dashboard JSON files at
`dashboards/*.grafana.json` and wires the embedding contract.

## Acceptance criteria

1. Three Grafana dashboard JSON files at:
   - `dashboards/tenant-cost-drilldown.grafana.json` (~200 lines)
   - `dashboards/fleet-cost-rollup.grafana.json` (~200 lines)
   - `dashboards/anomaly-investigation.grafana.json` (~200 lines)
2. Each dashboard:
   - declares `schemaVersion >= 39` (Grafana 10.x baseline).
   - templates a `$tenant_id` variable on `label_values(...)`.
   - templates a `$regulatory_pack` variable.
   - has at least 6 panels (matching the spec in
     `dashboards/tenant-cost-drilldown.md`).
   - uses Mimir datasource (UID templated; resolved at import).
   - has no embedded secrets, no embedded URLs to non-Mimir sources.
3. A `oya-check-grafana-dashboards-tenant-scoped` gate enforces that
   every panel's `expr` references `$tenant_id` OR is explicitly
   marked `panel.fleet_scope: true`.
4. The API tier (IP-005) exposes `GET
   /v1/tenants/{tenant_id}/dashboards/{dashboard}/embed-url` that
   returns a short-lived (5min TTL) signed Grafana URL.
5. Cedar policy `ops-finops-dashboard-access.cedar` (IP-007) governs
   who can request which dashboard.
6. CI lane `dashboards-import-smoke` green: imports each dashboard
   JSON into a dev Grafana, confirms no panel errors.

## File-level work plan

1. `dashboards/tenant-cost-drilldown.grafana.json` — 7 panels:
   headline, cost-by-cost-center, cost-by-workload-class,

2. `dashboards/fleet-cost-rollup.grafana.json` — 5 panels: fleet

3. `dashboards/anomaly-investigation.grafana.json` — 6 panels:
   alert-context, time-series-vs-baseline, contribution-by-
   dimension, deploy-correlation, related-runs, action-buttons.
4. `dashboards/_overlays/embedding.json` — embedding metadata
   (which dashboards are embeddable + per-panel scope rules).

## Embedding contract

When a tenant requests `GET /v1/tenants/T/dashboards/cost-drilldown/
embed-url`, the API:

1. Authzs via Cedar (`Action::"EmbedDashboard"`,
   `Resource::"Dashboard::cost-drilldown"`).
2. Generates a Grafana signed-URL with:
   - `$tenant_id=T` (forced; cannot be overridden client-side).
   - `$regulatory_pack=<from-jwt>`.
   - `var-tenant_locked=true` (Grafana's locked variable feature).
3. Signs with a per-environment HMAC key (rotated quarterly per
   IP-015's broader rotation cadence).
4. Returns `{ url, expires_at }` with 5min TTL.

## Panel SLI ties

- Drill-down headline panel binds to
  `slos/tenant-invoice-render-latency.openslo.yaml`'s SLI metric.
- Anomaly markers panel binds to the
  `TenantCostAnomalySpike` alert defined in PrometheusRule.
- FOCUS export availability panel binds to
  `slos/focus-export-availability.openslo.yaml`.

## Locale + currency in panels

- Grafana templating supports `$locale` and `$currency` as overrides.
- Default is `usd`; KR pack defaults to `krw` and uses Mimir's
  rate-conversion recording rule.
- Panel titles + axis labels use i18n key references resolved by
  the embedding UI; not hardcoded English.

## Risk + mitigation

- **Risk**: tenant-id leak via panel that forgets `$tenant_id`
  filter. **Mitigation**: `oya-check-grafana-dashboards-tenant-
  scoped` gate per criterion 3; CI BLOCKER.
- **Risk**: dashboard JSON drifts when Grafana team edits in UI.
  **Mitigation**: dashboards are managed-via-code; the embedding
  contract test imports the file and asserts no diff vs runtime.
