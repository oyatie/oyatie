# IP-journey-j82-risk-and-explanation - intelligence

## Goal

Implement the `risk-and-explanation` slice for `intelligence` so j82 can satisfy `KR-FSS` without leaking tenant data, collapsing provider-BYOK and encryption-BYOK meanings, or bypassing Cedar.

## PRD row alignment

- PRD anchor: microservices/intelligence/PRD.md when present, otherwise the service manifest and architecture surface for that microservice.
- Journey anchor: docs/user-journeys/j82-kr-fss-financial-fraud-24h-freeze/.
- Regulator article focus: Electronic Financial Transactions Act KR fraud response.
- Rigor row: documentation-rigor.md section 2 IP row; one service, one single-PR-sized implementation plan.

| File | Purpose | Notes |
|---|---|---|
| `microservices/intelligence/contracts/openapi/j82-risk-and-explanation-v1.yaml` | OpenAPI 3.2.0 REST surface | External read/write or admin action |

| `microservices/intelligence/contracts/proto/j82-risk-and-explanation-v1.proto` | proto3 internal RPC | Service-to-service call path |

| `microservices/intelligence/runbooks/j82-risk-and-explanation-rollback.md` | Rollback and incident path | Includes regulator deadline handling |
| `microservices/intelligence/tests/j82_risk_and_explanation_test.rs` | Integration tests | Positive, negative, rollback, audit |

## Data model

Primary object: `kr-fss-fraud-freeze` with tenant_id, subject_id, pack_id, jurisdiction_code, purpose, data_class, deadline_at, byok_provider_ref, byok_encryption_ref, and prior_seal_ref.
The service may store a local projection only when it can be rebuilt from the audit-chain and source-of-truth service. Mutable state must carry tenant_id and data_class.

## Cedar fragment

```cedar
permit (principal is Principal, action == Action::"j82.intelligence.risk-and-explanation", resource is JourneyObject) when {
  principal.tenant_id == resource.tenant_id &&
  resource.pack_overlay == "KR-FSS" &&
  context.jurisdiction == "KR" &&
  context.data_class_allowed == true &&
  context.audit_chain_required == true
};
```
