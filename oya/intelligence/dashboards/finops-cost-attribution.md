# FinOps Cost Attribution (intelligence)

## Purpose

Tenant-, audience-, provider-, model-, modality-, pack-attributed cost accounting for the
intelligence µservice. Read-side projection lives in the `finops` µservice; this document
defines the dashboards' shape, source queries, and chargeback workflow.

## Dashboard panels

### Cost by tenant × audience × pack

```promql
sum(rate(oya_intelligence_dispatch_cost_usd_total{}[30d])) by (tenant_id, audience, pack)
```

### Cost by provider × model

```promql
sum(rate(oya_intelligence_dispatch_cost_usd_total{}[30d])) by (provider, model)
```

### Cost by modality

```promql
sum(rate(oya_intelligence_dispatch_cost_usd_total{}[30d])) by (modality)
```

### Cost owner mix (provider-credential BYOK vs platform-default, ADR-0255 §D-4)

```promql
sum(rate(oya_intelligence_dispatch_cost_usd_total{}[30d])) by (cost_owner)
```

### Platform-default cost float (B2C)

```promql
sum(rate(oya_intelligence_dispatch_cost_usd_total{cost_owner="platform_default"}[1d])) * 86400
```

## Chargeback workflow

1. `finops` µservice projects audit-tap cost records into per-tenant ledger.
2. Monthly close: `finops-worker` aggregates by (tenant, audience, provider, model, modality, pack).
3. Per-tenant invoice generated from the aggregation (platform-default cost float absorbed by
   oyatie; provider-credential BYOK (ADR-0255 §D-4) + production-pass-through priced at zero markup; markup applied only to
   negotiated tiers).
4. Tenant operator views per-call cost in the cloud-scm developer console.

## Forecast

Quarterly forecast generated by `eval-worker` FinOps projection:
- 90d daily dispatch volume per (tenant, audience, modality) → linear regression.
- Per-tenant growth trend.
- Per-pack pricing differences.
- Per-provider price-change events.
