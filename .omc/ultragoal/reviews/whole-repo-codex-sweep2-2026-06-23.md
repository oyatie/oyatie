### The single most urgent item

**The CI ratchet launders new debt in-PR because suppression baselines/signoffs are
candidate-owned, not merge-base-anchored — and the founder signoff door trusts unsigned
JSON.** (generated-faces CRITICAL + 4 HIGH, pipeline HIGH.) This is the same systemic
class the founder was bitten by twice (`gate-baseline-pr-push-asymmetry-false-green`):
a gate that evaluates the candidate tree against a candidate-owned baseline can be made
green by editing the baseline in the same commit. The firewall signoff door makes it
worse: `SignOff::from_value` accepts a live `(gate, code, key)` exemption with **no
verified signer, signed digest, expiry, ADR binding, or one-time token**, and the
inert-signoff detector won't fire because the laundered key is live. Net effect: a PR
can add a new unauthenticated route, a new tier inversion, new friction debt, or new
embedded-asset skips, suppress each one in the same change, and pass `oya-ci-required`
green. This is the structural backstop the whole "pipeline = universal hermetic product"
doctrine depends on, and it is forgeable.

### Top cross-cutting themes per dimension

- **docs** — The authoritative agent contract (`docs/AGENTS.md`) and the root hub still
  mandate *superseded* CI doctrine (ADR-0513/Jenkins/Prow/multispectrum) and point
  agents at **phantom files**. Generated indexes (ADR-INDEX, decisions.json) are stale
  by ~70 ADRs and link to deleted paths. The markdown-retirement policy is past-due and
  unimplemented. Class: **stale-authority-surface with no freshness gate.**
- **ssot** — Multiple "single control planes" (root-hub-pointers, masterplan,
  agent-operating-contract, architecture-map, manifests-index, artifact/catalog
  registries) point at the **removed `microservices/` and top-level `crates/` trees** and
  still encode the **retired Oya VCS** as live promotion authority. Class: **generated
  SSOT never regenerated post-reorg; `migration_phase: complete` asserted over missing
  files.**
- **faces** — Generated suppression artifacts (signoff, authz baseline, tier-acyclicity
  baseline, friction/embedded-asset baselines) are **candidate-owned and unsigned**, so
  the meta-gates permit in-PR debt growth. Class: **baseline-laundering / non-ratcheted
  meta-gates.**
- **pipeline** — Required merge gate has green-when-should-be-red holes (PR FULL-tier
  skips `buck2 test`, rename/copy launders generated bytes) and **non-hermetic lanes in
  the required fan-in** (live Postgres, public GitHub/Node/CDN bootstraps). Class:
  **required context is neither test-complete nor hermetic.**
- **stack** — The crypto/transport posture doctrine is **factually false in the lock**:
  `ring` and `quinn` are resolved despite a zero-ring claim, `reqwest` resolves twice
  despite "hyper-only", native trust stores are pulled despite webpki-only, and the Buck
  graph **doesn't match Cargo.lock**. Toolchains are host-resolved, not hermetic. Class:
  **stated supply-chain invariants unverified and violated; no drift gate.**
- **architecture** — `libs/` repeatedly imports **product app/facade/kernel crates**
  (gRPC adapter, REST runtime, outbox HTTP adapter, tenant middleware), inverting the
  dependency direction; storage adapters define the IAM contract boundary; a platform
  residency kernel is wrong-homed under `network/`. Class: **shared-infra-imports-product
  / adapter-defines-the-port layering inversions.**
- **hygiene** — Public binaries ship **mock transports and TODO-only/stub modules as
  runtime behavior**; retired `cloud/cloud-*` and `oya/oya-*` husks remain first-class
  inventory with live SLOs/catalogs and no Rust; a safety hook **fails open**; naming
  governance still derives from the retired `oya-` brand. Class: **husk/stub/slop sprawl
  presented as real inventory; governance-theater that fails open.**
- **test-coverage** — Entire money and substrate capabilities **declare a full ladder in
  PRD/AC but ship zero executable tests** (payments), or stop at fixture/unit tier with
  no concurrency/property/integration/failure-injection (payroll, billing ledger,
  workflow durability, kernel boot/syscall, ksync loom). Several tests **pass for the
  wrong reason** (CloudEvent privacy, target-parity empty-corpus-green). Class:
  **ladder declared, lower tiers dark or absent; "unit green" masquerading as tested.**
- **best-practices** — Live network adapters (provider failover, OpenBao, Hyper
  listener) have **no deadlines/backpressure and drop failures**; SCIM read ports
  **erase backend failures into empty results**; secret-bearing structs **derive `Debug`**
  over token material. Class: **fault/timeout/secret-handling primitives missing on live
  I/O paths.**

## (b) CRITICAL + HIGH findings

### CRITICAL

#### C1 [faces] Firewall signoff door trusts unsigned JSON as founder approval
`cloud/cloud-ci/gates/oya-cloud-ci-firewall-app/src/lib.rs:291`
**Impact:** `SignOff::from_value` ignores `_provenance.signings` and builds exemptions
only from `_sign_off_additions`; `compare`/`ratchet_growth` then suppress
regressions/growth for matching keys. A PR can add a live `(gate, code, key)` to the
signoff JSON with **no verified signer, signed digest, expiry, ADR binding, or one-time
token**; inert-signoff detection won't fire because the key is live. The single most
load-bearing governance door is forgeable by editing JSON.
**Fix:** make every signoff addition a structured **signed** record bound to the exact
`(gate, code, key)` tuple and to the change identity; reject unsigned/unbound additions;
add a RED fixture for a live unsigned `_sign_off_additions` entry.

#### C2 [hygiene] Public provider-pool binary ships mock transport as runtime behavior
`oya/intelligence/crates/oya-intelligence-provider-pool-app/src/main.rs:355`
**Impact:** the **public** `oya-intelligence-provider-pool` binary (Cargo.toml:54,
BUCK:30) wires in-memory adapters and a mock transport returning HTTP 200 `pool.mock`
responses (line 751 admits real transport is "later"). It can pass smoke/deploy checks
while doing **zero real provider dispatch** — a deployable husk.
**Fix:** remove/privatize the binary until live transport exists, or make production
routes return typed `501`; keep mock transport behind test-only fixtures.

#### C3 [test-coverage] Payments money path declares a full ladder but has no executable tests
`oya/payments/PRD.md:1365`
**Impact:** AC-P-01..15 require k6 load, idempotency, RLS, property, refund, OAuth, and
PSP-failover tests, but `oya/payments` has **no tests dirs, no inline Rust tests, and no
`rust_test` targets** across `oya/payments/crates/*/BUCK`. Charges, refunds, payouts,
subscriptions, PSP routing, and webhooks can regress with CI green. The most
money-critical product has the emptiest ladder. `[XREF]` the code-security reports flag
the *placeholder-payments* logic (C24/C25 main); this is the orthogonal **test-absence**.
**Fix:** add unit/property/contract/integration/E2E/load/failure-injection tests wired
into Buck/nextest/k6 CI — idempotency replay, concurrent same-key, fake-PSP brownout,
refund tax reversal, subscription state-machine properties.

#### C4 [test-coverage] Kernel syscall/boot ladder is skipped or manual-only
`cloud/cloud-kernel/BUCK:3`
**Impact:** the bare-metal kernel binary and arch backends are Buck-incompatible/skipped;
the host harness is excluded and documented as a **manual cargo command**
(`cloud/cloud-kernel/Cargo.toml:21`). The matrix demands build-both, boot-both, golden
trace, differential oracle, and LTP, yet only **49/318 aarch64 and 55/375 x86_64
syscalls are differential-verified**. Unit/host-green masquerades as "kernel tested";
contract, boot-integration, E2E/LTP, failure-injection, and load tiers are missing.
(Companion CRITICAL: **ksync lock-free concurrency checks are dark** —
`cloud/cloud-kernel/crates/oya-cloud-kernel-ksync-kernel/BUCK:1` — loom/Miri model tests
are `cfg(loom)` + manual `RUSTFLAGS`, so CI never exercises the adversarial interleavings
that prove no double-dequeue/lost element.)
**Fix:** add required CI targets for both-arch build/boot/golden-trace/syscall-matrix-drift/
LTP/static-binary conformance + kernel failure/load fixtures; make the host harness a
first-class Buck/Cargo-gated test; add a gated loom Buck target with bounded preemptions
+ Miri/sanitizer and fail CI if the model-check tier is not run.

#### C5 [docs] Authoritative agent contract mandates superseded CI doctrine
`docs/AGENTS.md:57`
**Impact:** the scoped operating contract — `docs/AGENTS.md` is the authoritative agent
entry surface per root `CLAUDE.md` — tells agents ADR-0513/Jenkins/Prow/multispectrum
evidence are current, while AGENTS.md:13-28, CLAUDE.md, ADR-0515:52-88, and
`.github/workflows/oya-ci-required.yml` make GitHub Actions + single `oya-ci-required` the
authority and retire multispectrum enforcement. Every agent following the contract produces
or requires **obsolete evidence and CI gates** — the docs-staleness slice rated this
CRITICAL and it is the single most urgent docs item.
**Fix:** rewrite `docs/AGENTS.md` against ADR-0515; remove ADR-0513/Jenkins/Prow/
multispectrum requirements; point only to the current `oya-ci-required` contract.

#### faces

- **Authz baseline can absorb new unauthenticated routes in the same PR** —
  `cloud/cloud-ci/gates/oya-cloud-ci-authz-coverage-app/src/lib.rs:2196`. `evaluate_keyed`

  `cloud/cloud-ci/gates/oya-cloud-ci-tier-dependency-acyclicity-app/src/lib.rs:914`.
  `evaluate` labels a violating edge `Baselined` solely by membership in the **candidate**

  regressions. Same candidate-owned suppression at port-placement
  (`oya-cloud-ci-port-placement-app/src/lib.rs:608`). **Fix:** ratchet candidate baselines
  vs merge-base/trusted baselines, fail on additions; allow shrink-only burn-down; require
  signed scoped signoff for growth.
- **Meta-gate baselines admit review-visible laundering instead of structural enforcement**
  — `cloud/cloud-ci/gates/oya-cloud-ci-friction-accounting-app/friction-accounting-baseline.json:2`.

  the baseline/ceilings in the same change. **Fix:** baseline-shrink-only meta-gate that
  reads merge-base baseline/ceilings and rejects added keys / raised ceilings unless under

#### stack / supply-chain

  **Fix:** remove QUIC/http3 activation, pin rustls/webpki/aws-lc features so `ring` is
  absent, add cargo-deny bans for `ring` and `quinn`. *(Consistent with the founder

- **Reqwest remains a workspace dependency and resolves two versions** — `Cargo.toml:787`.
  Workspace declares `reqwest 0.13` despite "hyper client, not reqwest"; `Cargo.lock:3966`
  also resolves `reqwest 0.12.28` → duplicate HTTP client stacks + QUIC/native-root fanout.
  **Fix:** migrate adapters to the hyper transport port; remove workspace `reqwest`, or
  temporarily unify all crates on one version with http3/native-root features off.
- **TLS graph pulls native trust stores despite webpki-only doctrine** —
  `third-party/BUCK:6824`. `Cargo.toml:775` says `hyper-rustls` uses webpki roots with no

  `Cargo.lock:10567` confirms `rustls-native-certs` depends on `openssl-probe`. TLS now
  depends on host trust-store packages. **Fix:** webpki-root features only; purge
  `rustls-native-certs`/`rustls-platform-verifier`/`openssl-probe`; gate lock/Buck output
  against native trust-store deps.
- **Buck toolchains are host-resolved, not hermetic** — `toolchains/BUCK:8`. Uses
  `system_rust_toolchain` via rustup/PATH and hard-codes `/usr/bin/clang` + `/usr/bin/ar`.

  attestable from checked-in inputs (violates the cold-required release/SBOM doctrine).
  **Fix:** hermetic Buck rust/cxx toolchains backed by content-addressed archives/images
  with SHA256/SLSA provenance; remove rustup/PATH and `/usr/bin` assumptions.

- **IAM storage contracts are public adapter crates** —

#### best-practices (Rust)

- **SCIM read ports erase live backend failures into empty results** —
  `libs/oya-shared-scim-server-kernel/src/lib.rs:455`. `UserStore`/`GroupStore` reads return
  `Vec`/`Option`, so the Postgres adapter converts tx/tenant-GUC/query/commit/JSON-decode
  failures into `Vec::new()`/`None` (`iam/adapters/identity-scim-store-postgres/src/lib.rs:300,
  :361, :458, :572, :596`). Callers cannot distinguish "not found" from DB outage / RLS
  failure / corrupt payload — a fail-open data-availability defect. **Fix:** read ports
  return `Result<_, ScimStoreError>`; propagate sqlx/decode/commit errors with operation +
  tenant context; map store failures to SCIM 500; reserve empty/None for real absence.
- **Provider failover can hang forever on upstream I/O** —
  `oya/intelligence/crates/oya-intelligence-provider-pool-app/src/lib.rs:1487`.
  `HyperProviderInvocationTransport` has no timeout fields (:1195); awaits non-stream
  request (:1487), body collect (:1514), stream request (:1335), stream chunks (:1384)
  with no request/first-byte/body/stream-idle deadlines. A wedged provider stalls dispatch
  indefinitely so fallback + health-marking never run. **Fix:** add configured deadlines,
  wrap awaits with `tokio::time::timeout`, classify elapsed as retryable transport failure,
  record provider health before fallback.
- **OpenBao credential resolution has no network deadlines** —
  `oya/intelligence/crates/oya-intelligence-credential-resolver-adapter/src/openbao_kv.rs:287`.
  Bare Hyper client (:260), awaits `client.request` (:287) + body collect (:299) with no
  connect/request/body deadlines. A stalled vault pins credential issuance and every waiting
  caller. **Fix:** explicit OpenBao timeout config, wrap request/body with timeout, map
  elapsed to typed credential-issue failures, test stalled-header/stalled-body.
- **Live credential adapters bridge async I/O through blocking sync ports** —
  `oya/intelligence/crates/oya-intelligence-credential-resolver-adapter/src/openbao_kv.rs:375`.
  `CredentialHandleIssuerPort` is synchronous (usecase `src/lib.rs:134`), forcing OpenBao to
  `block_in_place(|| Handle::current().block_on(...))`; the Anthropic subscription adapter
  repeats it (`...anthropic-subscription-adapter/src/lib.rs:267`). Runtime-dependent, panics
  on incompatible Tokio runtimes, makes request-path refresh non-cancellable. **Fix:** make
  live credential/auth ports async end-to-end, or split sync/offline from async/live ports;
  if a sync bridge remains, isolate behind an owned runtime/thread boundary and cover
  no-runtime + current-thread-runtime in tests.
- **Shared Hyper listener has unbounded connection tasks and drops failures** —
  `libs/oya-http-runtime-hyper-adapter/src/lib.rs:336`. `serve_listener` ignores accept
  errors (:336), spawns one untracked task per accepted connection (:344), discards
  `serve_stream` errors (:345). A slow/erroring client population creates unbounded tasks;
  production loses structured evidence for accept/protocol/connection failures. **Fix:**
  configurable connection semaphore/backpressure, track spawned tasks for shutdown,
  instrument accept/connection failures with structured tracing, decide which accept errors
  are fatal.
- **Cloud-OS secret types derive `Debug` and expose token material** —
  `cloud/cloud-os/crates/oya-cloud-os-secrets-domain/src/bundle.rs:687`. `ClusterIdentity`,
  `Token`, `SecretsBundle` derive `Debug` while carrying cluster shared secrets + bootstrap/
  join tokens (:687/:716/:798); `JoinToken` derives `Debug` over the full token
  (`...trustd-domain/src/token.rs:13`); cluster-mgmt `Secret`/`SecretsBundle` repeat it
  (`...cluster-mgmt-domain/src/gen.rs:23, :60`). Any panic / trace field / `{:?}` can dump
  root-of-trust material. **Fix:** remove derived `Debug`; implement redacted `Debug`
  emitting only id/fingerprint/length; wrap secrets in redacting newtypes with private
  fields; add tests asserting `format!("{:?}")` excludes raw secret strings.
