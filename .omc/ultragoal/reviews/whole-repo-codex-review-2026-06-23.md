### Top cross-cutting / systemic classes

1. **Caller-supplied authorization is trusted as the authz decision (Cedar-PDP bypass).** The single most pervasive and most dangerous class. At least **11 distinct trust boundaries** accept a `{decision_id, tenant_id, principal_id, allowed_surfaces}` blob *inside the request DTO* and "validate" it by string-comparing fields against the same request, never calling the cloud-iam Cedar PDP server-side. Surfaced independently by 8 lenses across IAM, secrets/KMS, tenancy, network (LB/VPC/DNS), audit, compliance/DSR, intelligence, observability, and financial. This directly repeats the AUTH-005/#768 antipattern the founder flagged: a control plane that passes all gates green while being forgeable. Every one is default-ALLOW-on-forged-input.

2. **Unauthenticated / self-attested mutation endpoints.** Routers mount lifecycle, provision, quota, teardown, suspend/retire, and admin mutations with **empty middleware chains** and no principal extractor at all — not even a forgeable blob. IAM principal suspend/retire, k8s control-plane provision/teardown, k8s tenant-quota PUT, console workspace admin dump, HR sensitive-read, tenancy operator scope-via-header. Any reachable network caller mutates other tenants' state.

3. **Cedar policy authorizes by `tenant_class` with an unconstrained action/resource wildcard.** The rendered Helm `cedar.yaml` template (`permit(principal, action, resource)` gated only on `tenant_class` + `microservice`) is copied across cloud-network, cloud-network-dns, cloud-kms, cloud-secrets, and cloud-iac. Same-class principals are over-authorized for every action across the microservice and across tenants in that class. No `tenant_id == resource.tenant_id` binding anywhere.

4. **Fingerprint-less / mis-scoped idempotency keys across all money & event paths.** Replay by key only (no request-body fingerprint) silently under/over-bills, drops changed events, double-applies credit notes, and collapses distinct events. Global (non-tenant-scoped) idempotency maps let tenant A poison tenant B. Spans billing metering, billing ledger, credit notes, accounting journal, payroll, workflow execution, outbox kernel, community moderation.

5. **Unchecked / saturating money & integer arithmetic.** `+=` on `i64`/`u64` and `saturating_add/sub` across invoice totals, journal totals, payroll deltas, token expiry, and tax validation. Overflow either panics (DoS) in checked builds or wraps/clamps silently, letting a corrupted-but-"balanced" ledger pass invariant checks.

6. **Fail-open at the trust boundary.** Missing durable state → silently boot empty (KMS directory, audit ledger, tenancy RLS store → in-memory). Missing config → serve without the RLS boundary. Validator binary absent (`cargo` spawn fails) → gate returns Ok. Internal guard error → allow the git command. Default approval handler → accept command/file-change. "Absent = valid empty chain" erases audit history without a tamper signal.

7. **CI gates have green-when-they-should-be-red holes + shell/CLI merge-authority leaks.** Rename/copy launders generated bytes into source; PR FULL-tier ratchet skips tests; exempt path prefixes let mutating descendants bypass authz coverage; absolute include literals are non-blocking skips. Plus a local shell script (`oya-ci-post.sh --skip-verify`) can **forge required green merge contexts** — a direct merge-authority bypass.

8. **Deployable binaries that build green but do nothing / ship placeholders.** Office API/gateway/drive/worker `run()` is empty; `oya-flags` hits a TODO and returns Ok; payments Helm points production at placeholder charge code with no money-movement; CAPI control-plane adapter returns `Unimplemented`. "Builds green" ≠ "serves traffic" — and SLO manifests claim availability the binaries cannot deliver.

9. **Hot-path full-store scans + unbounded clones (no indexes).** Kernel scheduler/wait/VFS, COSI store list, cell placement, dcops capacity admission, object/analytics/audit reads — all O(total) under a global lock or with deep boxed clones, none affected-set-driven. Does not meet a hyperscale substrate bar.

10. **SSRF via prefix-only endpoint validation** (`starts_with("https://")` admits `169.254.169.254`, loopback, `kubernetes.default.svc`) in network OCI/selfhosted adapters and intelligence provider base-URL override; **plus** in-process CLI subprocess execution carrying live provider secrets (intelligence drivers, lane supervisor `--dangerously-bypass-approvals-and-sandbox`).

### Single most urgent item

**The caller-supplied-authorization Cedar bypass on the IAM policy-publish + workload-authorize + principal-lifecycle surfaces** (`iam/ports/policy-cedar-api/src/rest/mod.rs:238`, `iam/facade/identity-workload-rest/src/lib.rs:654/743`). IAM is the root of trust for the entire fleet's authz. Forging `X-Principal-*` / `X-Authorization-*` headers lets a caller **publish Cedar policy versions** that grant themselves control-plane access or deny other tenants, **authorize as any workload**, and **suspend/retire arbitrary principals** — all unauthenticated. Every other service's authz decision is downstream of policies this surface can be made to publish. Fix this seam first; it is the keystone of systemic class #1.

## (b) CRITICAL findings

Each tagged with the lens(es)/slice(s) that surfaced it.

### IAM (identity / authz root of trust)

**C1. Policy publish trusts caller-supplied authorization headers** — `iam/ports/policy-cedar-api/src/rest/mod.rs:238` (and binding gap at `iam/ports/policy-cedar-api/src/lib.rs:665`, HIGH). [iam-sec]
`publish_handler` copies `X-Principal-*`/`X-Authorization-*` straight into the publish request; the guard only checks string consistency + presence of `cedar.policy.publish`. **Impact:** a direct caller forges headers and publishes Cedar policy versions granting self control-plane access or denying tenants — fleet-wide authz takeover. **Fix:** derive tenant/principal from verified mTLS/SVID or verified bearer, call the Cedar PDP server-side, reject missing/denied; if decision evidence crosses hops make it signed, short-lived, audience-bound, and bound to principal/action/policy-id/version/scope/request-id.

**C2. Workload `/authorize` accepts forged active principals** — `iam/facade/identity-workload-rest/src/lib.rs:654` (gRPC twin `grpc/mod.rs:270`/`:298`). [iam-sec, iam-cor]
Builds an Active `WorkloadPrincipal` from request-body tenant/workload/capability/scopes/claims with no token or mTLS validation. **Impact:** any caller self-attests identity and receives Cedar ALLOW decisions as that workload. **Fix:** remove the bare-authorize surface or require authenticated PEP identity (mTLS/SVID + signed verified-principal evidence); route normal clients through token-validated authorize.

**C3. Principal lifecycle mutation exposed with no authn/authz** — `iam/facade/identity-workload-rest/src/lib.rs:743`. [iam-sec, iam-cor]
`POST /principals/{id}:suspend|retire` parses only the path verb then mutates repository + denylist. Tests post `{}` and assert success. **Impact:** any reachable caller suspends/permanently retires (tombstones) arbitrary workload principals. **Fix:** require verified admin/control-plane principal + Cedar authorization for Suspend/Retire on the target resource; 401/403 before `lifecycle_transition`; audit denied + successful.

**C4. Token authorization resolves workload state without tenant scoping** — `iam/facade/identity-workload-app/src/lib.rs:484`. [iam-cor]
Loads lifecycle + denylist state by `WorkloadId` only; `WorkloadId` is just `wl_*`, so a valid `ten_attacker/wl_shared` token satisfies the existence/lifecycle gate against a `ten_victim/wl_shared` record, then Cedar evaluates attacker-supplied attributes. **Impact:** cross-tenant isolation break on REST + gRPC token paths. **Fix:** key lookups by `(TenantId, WorkloadId)` or compare persisted tenant/capability/trust-domain against the verified token principal; deny on mismatch; add same-id cross-tenant regression.

### Secrets / KMS

**C5. KMS encrypt/decrypt trusts caller-supplied authorization** — `secrets/ports/kms-api/src/lib.rs:827`. [secrets-kms-sec]
`validate_authorization` checks only non-empty `decision_id`, tenant/principal equality, and `allowed_surfaces` membership. **Impact:** a caller forges the blob and authorizes KMS decrypt/encrypt with no verified PDP decision. **Fix:** remove caller-controlled authorization; derive principal from mTLS/OIDC, call Cedar PDP server-side, bind to tenant/key/action/resource/data-class/purpose/request-id/expiry/policy-version, fail closed.

**C6. Sealing root provisioned as exportable single-custodian OpenBao key** — `secrets/adapters/kms-openbao/src/root_custody.rs:128`. [secrets-kms-sec]
`provision_root_command` sets `exportable=true`; `fetch_root_export_command` exports the full root; provenance is literally `OpenBaoTransitionalSingleCustodian`. **Impact:** compromise of one export permission/token/endpoint/operator retrieves the entire cell sealing root → unwraps all KEKs/DEKs. **Fix:** remove production full-root export; non-exportable HSM/PKCS#11 root custody or Shamir M-of-N dual control; startup refuses single-custodian/exportable provenance in prod; rotate/shred every exportable root ever created.

### Tenancy isolation

**C7. Tenant operator scope is self-attested via header** — `tenancy/facade/tenant-lifecycle-app/src/lib.rs:446`. [tenancy-isolation-sec]
One shared `TENANCY_TENANT_OPERATOR_TOKEN`; after bearer match it copies caller-controlled `x-oya-tenant` into `CallerIdentity.tenant_scope`; PDP then permits per-tenant admin when asserted scope == target. **Impact:** any operator-token holder sets `x-oya-tenant: victim` and reads/provisions/suspends/resumes/retires any tenant. **Fix:** derive tenant scope only from verified cloud-iam/OIDC membership or server-side lookup; ignore caller tenant headers; regression proving operator token cannot select an unassigned victim.

**C8. Tenant creation authorizes itself from caller-supplied decision fields** — `tenancy/ports/api/src/lib.rs:534`. [tenancy-isolation-sec]
`TenantCreateApiRequest` carries `principal` + `authorization`; validator accepts any non-empty `decision_id` whose fields match the request and `allowed_surfaces=["tenant.create"]`. **Impact:** forge the blob, create tenants with no server-side PDP decision. **Fix:** remove authorization from the DTO, authenticate at boundary, call PDP server-side, bind allow to verified principal/action/resource/policy-version.

### Network / edge (caller-supplied authority)

**C9–C11. LB / VPC / DNS create trust caller-supplied authorization decisions** — `network/ports/lb/src/lib.rs:623`, `network/ports/vpc/src/lib.rs:657`, `network/ports/dns/src/lib.rs:572`. [edge-transport-sec]
All three validate authorization purely from caller-provided `CloudNetwork*ApiAuthorization` (non-empty `decision_id` + matching tenant/principal + `allowed_surfaces` entry). **Impact:** forge fields → create tenant-scoped load balancers / VPCs / DNS zones (full DNS control) with no verified PDP decision. **Fix:** delete request-supplied authorization; require an injected cloud-iam Cedar authorizer bound to principal/tenant/action/concrete-resource/audience/expiry; fail closed when authorizer absent/errors.

### Cedar wildcard policy (rendered Helm templates)

**C12–C13. cloud-network and cloud-network-dns Cedar policies permit every action by tenant class** — `cloud/cloud-network/iac/k8s/helm/templates/cedar.yaml:12`, `cloud/cloud-network-dns/iac/k8s/helm/templates/cedar.yaml:12`. [edge-transport-sec]
`permit` leaves action unconstrained, authorizes on `resource.microservice` + `principal.tenant_class`; forbid only blocks mismatched class, not mismatched tenant id. **Impact:** any same-class principal performs any action on any resource for that microservice, cross-tenant included. **Fix:** require `principal.tenant_id == resource.tenant_id`, explicit action allowlists, resource-type/id binding, cross-tenant/unknown-action deny tests.

**C14. cloud-IaC Cedar policy grants class-wide access to every action/resource** — `cloud/cloud-iac/iac/k8s/helm/templates/cedar.yaml:12`. [k8s-iac-arch]
Same wildcard `permit(principal, action, resource)` gated only on `tenant_class`. **Impact:** contributor-class principal authorized for cloud-iac reads/writes across the microservice boundary, including mutation/secret paths. **Fix:** explicit action/resource permits, bind principal tenant to resource tenant/microservice, explicit forbids for sensitive mutation/secret paths, policy tests.

### Audit / compliance

**C15. Audit event authorization is caller self-attested** — `audit/core/usecase/src/lib.rs:408`. [identity-audit-compliance-sec]
`validate_authorization` string-compares request-supplied `decision_id`/`tenant_id`/`producer_id`/`allowed_surfaces` against the envelope. **Impact:** forge fields → emit audit records (the system's tamper-evidence) with no verified principal or PDP. **Fix:** remove caller-supplied authorization; derive principal from mTLS/JWT, call Cedar PDP, fail closed, persist only server-issued signed decision reference.

**C16. DSR cascade execution authorizes caller-supplied principals** — `compliance/ports/dsr-usecase/src/lib.rs:842`. [identity-audit-compliance-sec]
Trusts `principal` + `authorization` in the request, checks only string match + DSR surface membership. **Impact:** fabricate tenant/principal/decision and execute Data-Subject-Request cascades (GDPR erasure) for that tenant. **Fix:** derive principal from authenticated transport, remove caller-controlled `allowed_surfaces`, call PDP for `dsr.cascade.execute`, default-deny on absent/invalid/stale/failed evidence.

### Intelligence

**C17. Provider drivers execute PATH-resolved CLIs with live provider secrets** — `oya/intelligence/crates/oya-intelligence-codex-account-adapter/src/lib.rs:34`. [intelligence-sec]
`spawn_for_message` resolves the provider secret and launches `Command::new("codex")` injecting `OPENAI_API_KEY`; sibling Claude/Gemini drivers do the same with `ANTHROPIC_API_KEY`/`GOOGLE_API_KEY`; supervisor wires them into the live path. **Impact:** PATH or image compromise replaces the binary and exfiltrates tenant provider credentials — via a forbidden CLI surface (violates the no-CLI + intelligence-must-be-in-process-HTTP doctrine). **Fix:** remove CLI drivers from production composition; in-process HTTPS adapters behind ports; if kept test-only use absolute attested paths, `env_clear`, fixed cwd, minimal allowlisted env, no env-carried secrets.

### Observability

**C18. Audit API trusts caller-supplied authorization evidence** — `observability/core/api/src/lib.rs:504`. [observability-arch]
Accepts `authorization.allowed_surfaces` from the request, checks only that it contains the audit surface; no PDP, signed-decision verify, expiry, nonce, or request binding. **Impact:** any authenticated principal self-grants `cloud.observability.audit.read`. **Fix:** cloud-iam Cedar PDP port at the boundary bound to tenant/principal/action/resource/request-hash/expiry/decision-id; fail closed unless verified.

### Kernel / OS (memory-safety + authz)

**C19. wait4 status writes can corrupt memory across page boundaries** — `cloud/cloud-kernel/.../arch-x86-64-adapter/src/process.rs:416` (aarch64 twin `:310`). [cloud-kernel-os-cor]
`sys_wait4` accepts any `user_range_ok(status,4)` but `write_u32` translates only the first page then does an unaligned 4-byte store through the identity alias. **Impact:** user places `status` at a page boundary → kernel writes into the next physical frame (kernel memory corruption / privilege escalation primitive). **Fix:** checked user-copy that translates every touched page, returns `-EFAULT` on any unmapped byte; handle cross-page pointers; propagate failure through immediate + blocked wait4.

**C20. apid authorization bypasses the required Cedar PDP** — `cloud/cloud-os/.../oya-cloud-os-apid-domain/src/auth.rs:99`. [cloud-kernel-os-cor]
Every apid call is decided from local `RoleSet` predicates + an override map; no Cedar PDP request in the sampled apid/kubeaccess paths. **Impact:** a role string alone grants method access; tenant/resource conditions and PDP deny/outage fail-closed never evaluated. **Fix:** route every decision through cloud-iam Cedar PDP (principal/action/resource/tenant/context), treat PDP errors as deny, keep local role parsing as identity-claim input only.

**C21. impersonation metadata can mint the internal `os` role** — `cloud/cloud-os/.../oya-cloud-os-apid-domain/src/interceptor.rs:83`. [cloud-kernel-os-cor]
`impersonate-roles` is parsed with `RoleSet::parse_ous` which accepts `os`; `PeerIdentity::impersonate` replaces caller roles with the requested set. **Impact:** any admin/impersonator sends `impersonate-roles: os` and satisfies `OsOnly` gates (Reset, Upgrade). **Fix:** forbid internal `Role::Os` in external metadata, restrict impersonation targets to grantable roles, enforce delegation via Cedar PDP before role replacement.

### k8s control plane

**C22. Control-plane admin API exposes provision/status/teardown without authorization** — `k8s/facade/control-plane-host-app/src/lib.rs:201`. [k8s-iac-arch]
`/admin/control-planes[/status|/teardown]` mounted to handlers with no principal extractor, PDP call, or middleware. **Impact:** any network caller requests managed control-plane lifecycle ops; once the live adapter is wired → unauthenticated management-cluster mutation. **Fix:** verified workload principal + Cedar authorization before every non-health route; default-deny; enforce managed-k8s policies; unauthenticated/wrong-scope/tenant-principal deny tests.

**C23. Tenant quota API allows unauthenticated quota mutation + reads** — `k8s/facade/tenant-quota-app/src/lib.rs:294` (and the Cedar adapter omits own-tenant binding, `k8s/adapters/tenant-quota-adapter-cedar/src/lib.rs:88`). [k8s-iac-arch]
`PUT /tenants/{id}/quota`, quota/usage reads, and checks have only path/body consistency checks — no principal, PDP, or tenant gate; the adapter's TenantAdmin policy never requires `principal.tenant_id == target_tenant_id`. **Impact:** any caller sets another tenant's quota ceiling, inspects usage, probes admission. **Fix:** fail-closed authn/authz middleware + Cedar PDP per tenant-scoped op + tenant-equality condition in the policy + cross-tenant deny tests.

### Financial

**C24 (CRITICAL #1 of financial). Unscoped `convert_tenant` permit bypasses tenant + role checks** — `cloud/cloud-billing/policies/conversion-gates.cedar:134`. [financial-cor]
Authorizes `convert_tenant` using only audit-chain context booleans; omits tenant scope, source/target class, contract binding, and finance/admin role predicates. **Impact:** a request satisfying the booleans bypasses the stricter tenant-conversion guard. **Fix:** fold audit-chain requirements into the tenant-scoped conversion rule, or require the same tenant/contract/class/role predicates here.

**C25 (CRITICAL #2 of financial). Production payments deployment points at placeholder charge code** — `oya/payments/iac/k8s/helm/values.yaml:3`. [financial-cor]
Helm selects `oya-payments-charge-app` for production, but the charge app/rest/usecase crates are placeholder structs — no charge/refund/payout execution, no Cedar authz, no idempotency store, no PSP boundary, no accounting/audit write. **Impact:** a production payments surface satisfies packaging while shipping no money-movement implementation (and no authz). **Fix:** remove the production claim until implemented, or implement handlers with default-deny Cedar + durable idempotency + PSP adapter + ledger/audit; add a gate failing placeholder-only payment packages.

### CI / merge authority

**C26. Rename/copy can launder generated output into a non-generated merge surface** — `cloud/cloud-ci/gates/oya-cloud-ci-generated-artifact-control-plane-app/src/lib.rs:479`. [cloud-ci-gates-cor]
`diff_candidate_path()` inspects only the destination for `R*`/`C*` records; renaming `foo.generated.json` → `foo.json` makes the generated source endpoint ignored and the destination unclassified, so the required PR diff-policy check returns green while generated bytes become source-owned. **Impact:** a contributor launders machine-generated bytes past the generated-artifact control plane. **Fix:** for rename/copy evaluate both endpoints; block when either matches a generated path rule unless both stay under generated-artifact control with a valid manifest transition; `R*`/`C*` regression tests.
