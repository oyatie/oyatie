# Portable delivery doctrine

This is the runtime-neutral survival surface for Oyatie's agent delivery doctrine. It mirrors the
operating rules without copying machine-owned path sets. Root `AGENTS.md`, `CLAUDE.md`, and
`docs/AGENTS.md` are session-loaded law; ADR-0711 explains the decisions; policy-as-data remains
the only authority for enumerated repository sets.

## Hyperscaler monorepo patterns first class

- Keep one protected admission path and distinguish observation, review approval, and protected
  CI authority. Green output never grants approval by itself.
- Use one isolated worktree and branch per implementation lane. Coordinator, implementer,
  reviewer, and babysitter remain distinct roles.
- Keep ownership, code, tests, operational evidence, and documentation with the capability that
  changes. Shared hubs have an explicit sole owner per wave.
- Bound parallelism by replicated state and contention, not by how many agents can be started.
- Prefer fail-closed, constant-work, shared-nothing automation with telemetry and explicit failure
  modes. The delivery pipeline is a product.

The full rationale and acceptance model live in ADR-0711 and the review lenses in
`docs/AGENTS.md`. Prose cites machine-owned sets rather than duplicating them.

## Amendment A docs and check surfaces

Documentation governance remains coupled to tracked integration/specification authority, not to
an editor runtime. Any tracked check daemon or process helper follows the merge executor declared
by the operating contract and ADR-0716. Comments preserve the reason for non-obvious controls;
generated artifacts are written only by their registered producer and verified for freshness.

## Amendment B repository shape

Every meaningful repository unit has an evaluated disposition in policy-as-data. New births under
frozen or vacated prefixes are refused; a reorganization records rationale, destination, redesign,
completed judgment, and challenges before moving files. Establish a defensible naming pattern
before applying it broadly. Deleting an existing fence requires explaining why it existed and what
now preserves its useful property.

## Amendment C operating patterns

`specs/agentic-operating-patterns.json` is the machine-readable KEEP/BAN catalog. Its rules carry
why: achieves, origin, rule, ensure, and overturn_when. Apply those rules as hypotheses that may be
challenged and explicitly overruled; never let them drift silently.

The irreducible posture is evidence before done, honest halt on missing authority, verified-empty
as a valid result, same-subsystem batching, one author-distinct adversarial reviewer, and fresh
evidence for each new HEAD. Invented work, dual truth, shared-working-directory mutation, silent
blocked success, and observation-as-authority are banned.

## Amendment D doctrine survival

Doctrine that exists only in a plan, chat, generated face, or local runtime directory has not
survived. A load-bearing change updates the session-loaded entry hub, owning ADR or policy-as-data,
and this portable mirror in the same wave. Generated artifacts are regenerated by their producer
and never edited by hand.

Enumerations come only from policy-as-data; prose cites JSON pointers. Claim and review evidence
names its documentation action. Any OVERRULE that changes doctrine lands the replacement rule and
bumps the applicable doctrine version atomically.

## Amendment E-1 decision-record path

Keep the durable `docs/decisions/ADR-NNNN-<topic>.md` shape. Numbered paths preserve chronology and
stable citations; indexes and frontmatter provide topic navigation. A mass rename for naming
optics is prohibited unless measured findability failure, a reviewed migration, and an explicit
OVERRULE replace this rule.

## Amendment F single independent-agent review authority

- **achieves:** autonomous planning, dispatch, and merge retain adversarial review without a human
  or reviewer-quorum bottleneck.
- **origin:** qualified-human and quorum requirements blocked complete autonomous work and treated
  forge account type as a proxy for trust.
- **rule:** one author-distinct independent reviewer agent's explicit `APPROVE`, bound to the exact
  current PR head and applicable plan digest, is sufficient review authority. Eligible `User`,
  `Bot`, and `Organization` accounts are equivalent. Human approval and reviewer quorum are not
  required. Any other or missing verdict blocks.
- **ensure:** a trusted packet proves exact PR/head/plan binding, immutable author/reviewer
  separation, eligibility, and freshness. Findings/threads, required CI, conflicts, branch
  protection, and operation-specific technical gates remain independent predicates.
- **overturn_when:** a recorded challenge proves single-agent review unsafe or unavailable and a
  replacement rule carrying all five fields lands same-wave.

One reviewer agent may apply every specialist lens implicated by a change. If no single agent is
eligible for the complete profile union, review blocks; it does not assemble a required quorum.
Additional review is optional information. Observation, CI, and review remain distinct predicates.

## Merge windows and advisory perimeter

Use the machine policy as the sole authority for merge-window and advisory-perimeter values. Keep
the hot set bounded, record babysit observations, and never use force-push or push loops as a
substitute for a clean protected pull request. Advisory automation may observe, classify, and
recommend; it may not self-approve, merge, invent authority, or widen scope from tool output.

## Limitations

This doctrine does not wire branch protection or a trusted review-packet producer by itself. It
does not retroactively promote historical review observations, fabricate missing evidence, bypass
technical predecessors (including an operation's recovery-train, security gate, or fresh-census
conditions), CI/conflict/thread/policy predicates, or authorize self-review. Machine-owned enumerations remain
outside this prose surface.
