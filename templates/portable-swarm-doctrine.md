# Portable delivery doctrine

This is the runtime-neutral survival surface for Oyatie's agent delivery doctrine. It mirrors the
operating rules without copying machine-owned path sets. The root `AGENTS.md`, `CLAUDE.md`, and
`docs/AGENTS.md` are session-loaded law; ADR-0711 explains the decisions;
`specs/integ-branch-envelopes.json` is the only authority for enumerated roots, planes, hubs,
freeze rows, merge windows, and daemon policy.

Repository-local `.claude/`, `.codex/`, `.cursor/`, and `.grok/` trees are ignored machine-local
runtime state. They are never doctrine, merge evidence, or required inputs in a clean CI checkout.
When an operator creates local `.codex/` content, Rust-first automation inspection still scans it;
ignored does not mean exempt from local policy checks.

## Hyperscaler monorepo patterns first class

- Keep one protected admission path and distinguish observation, review approval, and merge
  authority. Green output never grants approval by itself.
- Use one isolated worktree and branch per implementation lane. A coordinator, implementer,
  reviewer, and babysitter are distinct roles even when one person performs more than one role at
  different times.
- Keep ownership, code, tests, operational evidence, and documentation with the capability that
  changes. Shared hubs have an explicit sole owner per wave.
- Bound parallelism by replicated state and contention, not by how many agents can be started.
- Prefer fail-closed, constant-work, shared-nothing automation with telemetry and explicit failure
  modes. The delivery pipeline is a product, not a pile of local scripts.

The full rationale and acceptance model live in ADR-0711 and the review lenses in
`docs/AGENTS.md`. Machine path membership must cite `specs/integ-branch-envelopes.json#roots`,
`#planes`, and `#hubs.paths`; prose must not duplicate those sets.

## Amendment A docs and check surfaces

Documentation governance remains coupled to tracked integration/specification authority, not to
an editor runtime. Any future tracked check daemon or process helper belongs under `ci/facade/` or
`ci/process-kit/`, follows the merge executor declared by the operating contract and ADR-0716, and
never lives in an agent dot-directory. Comments preserve the reason for non-obvious controls;
generated artifacts are written only by their registered producer and verified for freshness.

## Amendment B repository shape

Every meaningful repository unit has an evaluated disposition in
`specs/integ-branch-envelopes.json#reorg_debt_freeze.rows`. New births under frozen or vacated
prefixes are refused; a reorg change records its rationale, destination, redesign, completed
judgment, and challenges before moving files. Naming follows `specs/naming-taxonomy.json`; establish
a defensible pattern before applying it broadly.

Root keep/replace/delete decisions apply the full review-lens battery from `docs/AGENTS.md`; leaf
changes inherit the recorded root judgment unless they introduce a new architectural choice.

Deleting an existing fence requires explaining why it existed and what now preserves its useful
property. A move that only changes paths, retains dual authority, or leaves a dead scanner is not a
completed redesign.

## Amendment C operating patterns

`specs/agentic-operating-patterns.json` is the machine-readable KEEP/BAN catalog. Its rules carry
why: achieves, origin, rule, ensure, and overturn_when. Apply those rules as hypotheses that may be
challenged and explicitly overruled; never let them drift silently.

The irreducible delivery posture is evidence before done, honest halt on missing authority,
verified-empty as a valid result, same-subsystem batching, adversarial review, and fresh evidence for
each new HEAD. Invented work, dual truth, shared-working-directory mutation, silent blocked success,
and observation-as-authority are banned.

## Amendment D doctrine survival

Doctrine that exists only in a plan, chat, generated face, or local runtime directory has not
survived. A load-bearing change updates the session-loaded entry hub, owning ADR or policy-as-data,
and this portable mirror in the same wave. Generated artifacts are regenerated by their producer and
never edited by hand.

Enumerations come only from `specs/integ-branch-envelopes.json`; prose cites JSON pointers. Claim and
review evidence names its documentation action. Any OVERRULE that changes doctrine lands the
replacement rule and bumps `#anti_drift.anti_drift_doctrine_version` atomically.

## Amendment E-1 decision-record path

Keep the durable `docs/decisions/ADR-NNNN-<topic>.md` shape. Numbered paths preserve chronology and
stable citations; indexes and frontmatter provide topic navigation. A mass rename for naming
optics is prohibited unless a measured findability failure, full reviewed migration, and explicit
OVERRULE replace this rule. The machine judgment is
`specs/naming-taxonomy.json#kinds.decision-record`.

## Merge windows

Use `specs/integ-branch-envelopes.json#merge_windows` as the sole machine authority. Keep the hot set
bounded, restack once per window, record babysit observations, and never use force-push, merge-trunk,
or push loops as a substitute for a clean protected pull request.

## Northstar daemon hotset and advisory perimeter

`specs/integ-branch-envelopes.json#daemon_hotset` and `#perimeter` define the daemon's bounded inputs
and advisory boundary. Automation may observe, classify, and recommend within that perimeter; it may
not self-approve, merge, invent authority, or widen its scope from tool output. Receipts record what
was observed and remain distinct from reviewer approval and protected admission.

## Limitations

This doctrine does not install or attest an agent sandbox, wire local hooks, flip branch
protection, or close the server-side review-admission gap tracked by F-PR5-06. It does not duplicate
machine-owned path enumerations, and it does not make ignored local runtime state a shared project
input. Local `.codex/` automation remains inspectable when present until the protected scan-scope
policy is deliberately retired through its own reviewed transition.
